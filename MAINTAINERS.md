# The Dayu Maintainers and Contributors

This is the authoritative role and responsibility roster for the Dayu system repository.
[GOVERNANCE.md](GOVERNANCE.md) defines appointments, reviews, decisions, and role transitions. Affiliation records
contributors' institutions; it does not determine eligibility or authority.

A community role does not by itself grant GitHub permissions. The [administration guide](docs/development/community-administration.md)
explains how actual access, [OWNERS](OWNERS), and generated [CODEOWNERS](.github/CODEOWNERS) are verified and synchronized.
The documentation website maintains its own roster for website responsibilities.

## Maintainers

All Maintainers share repository-wide review, merge, and stewardship responsibilities, including shared contracts,
compatibility, release coordination, and contributor support. Reviews and merges follow the
[governance policy](GOVERNANCE.md#technical-decisions-and-pull-requests) and require verified GitHub permissions.
Any Maintainer can help route a contribution to a qualified reviewer.

| Maintainer  | GitHub ID                              | Affiliation        | Email                     |
|-------------|----------------------------------------|--------------------|---------------------------|
| Wenhui Zhou | @[zwh2119](https://github.com/zwh2119) | Nanjing University | <whzhou@smail.nju.edu.cn> |
| Haoyang Su  | @[ShyEdge](https://github.com/ShyEdge) | Nanjing University | <shyshy@smail.nju.edu.cn> |

All Maintainers are listed as both reviewers and approvers in the root [OWNERS](OWNERS).
GitHub Actions validates that mapping and helps request reviews; generated [CODEOWNERS](.github/CODEOWNERS) connects
the approvers to GitHub's native review requirement. The [OWNERS guide](docs/development/owners.md) describes the
workflow. The `dayu-autostreamer/dayu-maintainer` team manages access, which is verified separately from this roster.
A TSC office adds no approval stage, and members holding several roles count as one person in a decision.
Repository administration is a separate operational duty; see the [administration guide](docs/development/community-administration.md).

## Availability and Emeritus Records

Contact a Maintainer above to discuss availability, handover, or taking on a responsibility. Role changes follow
[the governance process](GOVERNANCE.md#availability-emeritus-status-and-removal); review the roster and access at least
every six months. Record agreed Emeritus transitions with the member's former role and retain their contribution
credit. No Emeritus transitions are currently recorded here.
